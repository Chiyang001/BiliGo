## ✨ 功能特性

### 🔥 核心功能

#### 私信自动回复
- ✅ **关键词匹配回复** - 支持多关键词匹配，智能识别用户消息
- ✅ **文字/图片回复** - 支持发送文字消息或图片消息
- ✅ **默认回复** - 未匹配关键词时自动发送默认回复
- ✅ **区分用户类型** - 可为已关注和未关注用户设置不同的默认回复
- ✅ **仅回复新消息** - 可选择只回复程序启动后的新消息
- ✅ **回复次数限制** - 防止对同一用户重复回复，避免骚扰
- ✅ **持久化统计** - 用户回复次数持久化存储，重启不丢失

#### 评论自动回复
- ✅ **视频评论监控** - 自动监控最新视频的评论
- ✅ **实时检测** - 60秒检查间隔，及时发现新评论
- ✅ **关键词匹配** - 根据评论内容智能回复
- ✅ **独立配置** - 评论系统与私信系统完全独立
- ✅ **智能缓存** - 避免重复回复，自动清理过期缓存
- ✅ **详细日志** - 实时显示处理进度和回复统计

#### 关注者管理
- ✅ **新关注欢迎** - 自动向新关注者发送欢迎消息
- ✅ **取消关注告别** - 检测到取消关注时发送告别消息
- ✅ **重复关注检测** - 支持检测用户重复关注行为
- ✅ **智能间隔控制** - 默认10分钟检查间隔，最低30分钟，避免触发风控

### 🎯 高级特性

#### 邮件提醒系统（Ver.20260401 新增）
- ✨ **错误自动通知** - 系统错误时自动发送详细邮件
- ✨ **登录失效提醒** - 账号登录状态失效时立即通知
- ✨ **QQ邮箱支持** - 内置QQ邮箱SMTP配置，开箱即用
- ✨ **授权码配置** - 详细的授权码获取教程

#### 其他特性
- 🚀 **极速响应** - 0.05秒消息检测间隔，快速响应用户
- 🔄 **自动重启** - 长时间无消息时自动重启，保持系统稳定
- 📊 **实时日志** - 详细的运行日志，支持按类型筛选
- 🎨 **现代化界面** - 响应式设计，支持移动端访问
- 🔐 **安全可靠** - 本地运行，数据安全有保障

## 🚀 快速开始

### 1. 克隆项目

```bash
git clone https://github.com/Chiyang001/BiliGo.git
cd BiliGo
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

如果没有 `requirements.txt`，手动安装以下依赖：

```bash
pip install flask requests
```

### 3. 运行程序

```bash
python app.py
```

### 4. 访问界面

在浏览器中打开：
- **私信回复系统**: http://localhost:4999
- **评论回复系统**: http://localhost:4999/comment
- **系统日志页面**: http://localhost:4999/logs.html

### Docker 一键部署

无需安装 Python，适合服务器长期运行或多账号隔离部署。

**前置要求**：已安装 [Docker Desktop](https://docs.docker.com/get-docker/)（Windows/macOS）或 Docker Engine（Linux）。

#### 方式一：一键脚本

**Windows** — 双击或在项目目录运行：

```bat
docker-deploy.bat
```

**Linux / macOS**：

```bash
chmod +x docker-deploy.sh
./docker-deploy.sh
```

#### 方式二：Docker Compose

```bash
docker compose up -d --build
```

#### 方式三：手动构建镜像

```bash
docker build -t biligo:latest .
docker run -d \
  --name biligo \
  -p 4999:4999 \
  -v biligo-data:/data \
  --restart unless-stopped \
  biligo:latest
```

#### 数据持久化

容器内配置、规则、导出文件保存在 `/data` 目录（对应 Docker 卷 `biligo-data`）。首次启动会自动从镜像内复制默认配置模板。

如需将数据存到本地目录：

```bash
docker run -d -p 4999:4999 -v ./biligo-data:/data biligo:latest
```

#### 常用命令

```bash
docker compose logs -f      # 查看运行日志
docker compose restart      # 重启服务
docker compose down         # 停止并移除容器
docker compose pull && docker compose up -d --build  # 更新并重建
```

#### 可选：评论浏览器模式（Playwright）

默认镜像不含 Chromium。若 `comment_fetch_mode` 设为 `browser`，需自行构建带 Playwright 的镜像：

```bash
docker build -t biligo:browser -f Dockerfile.playwright .
```

## 📝 详细配置

### 获取 B站 Cookie

1. 登录 [B站](https://www.bilibili.com)
2. 按 `F12` 打开开发者工具
3. 切换到 `Application` 或 `存储` 标签
4. 在左侧找到 `Cookies` → `https://www.bilibili.com`
5. 找到并复制以下两个值：
   - `SESSDATA`
   - `bili_jct`

> **20260830+**：首次启动后会自动在 `config.json` 生成 `im_dev_id`（私信设备标识，每账号独立）。请勿手动改回旧版共用 ID，否则可能触发 HTTP 412 风控。

### 配置邮件提醒（可选）

#### 获取QQ邮箱授权码

1. 登录 [QQ邮箱](https://mail.qq.com)
2. 点击右上角 **设置** → **账号与安全**
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV 服务**
4. 开启 **IMAP/SMTP服务** 或 **POP3/SMTP服务**
5. 点击 **生成授权码**，按提示完成手机验证
6. 复制生成的授权码（16位字符）

#### 在系统中配置

1. 在 Web 界面找到 **邮件提醒配置** 区域
2. 勾选 **启用邮件提醒**
3. 填写：
   - **发送邮箱**: 你的QQ邮箱地址
   - **邮箱授权码**: 刚才生成的授权码（不是QQ密码！）
   - **接收邮箱**: 接收通知的邮箱（可以与发送邮箱相同）
4. 点击 **发送测试邮件** 验证配置
5. 点击 **保存邮件配置**

### 配置私信回复规则

1. 在 **关键词回复设置** 区域：
   - **规则标题**: 给规则起个名字（如：问候回复）
   - **关键词**: 输入关键词，用中文逗号分隔（如：你好，您好，hi）
   - **回复类型**: 选择文字回复或图片回复
   - **回复内容**: 输入回复的文字或选择图片
2. 点击 **添加规则**

### 配置评论回复规则

1. 访问 http://localhost:4999/comment
2. 配置方式与私信回复类似
3. 可以从私信配置导入规则

### 配置关注者欢迎

1. 在 **关注后回复设置** 区域：
   - 勾选 **启用关注后自动回复**
   - 选择回复类型（文字或图片）
   - 输入欢迎消息
   - 设置检查间隔（建议30分钟以上）
2. 点击 **保存关注回复设置**

## 📚 使用教程

### 基础使用流程

1. **配置账号**
   - 在 **账号配置** 区域填入 SESSDATA 和 bili_jct
   - （可选）配置错误提醒邮箱
   - 点击 **保存配置**

2. **添加回复规则**
   - 在 **关键词回复设置** 添加多条规则
   - 支持文字和图片两种回复方式
   - 可以启用/禁用单条规则

3. **配置默认回复**（可选）
   - 勾选 **启用默认回复**
   - 可以区分已关注和未关注用户
   - 设置不同的默认回复内容

4. **启动监控**
   - 点击 **开始监控** 按钮
   - 系统开始自动检测和回复私信
   - 在日志页面查看运行状态

### 高级功能

#### 时间间隔配置

在 **时间间隔配置** 区域可以调整：
- **消息监测间隔**: 检查新消息的频率（默认0.05秒）
- **发送等待间隔**: 两次发送消息的间隔（默认1秒，建议不低于1秒）
- **自动重启间隔**: 无消息时自动重启的时间（默认300秒）

#### 规则导入导出

- **导出配置**: 点击 **导出配置** 按钮，下载包含所有规则的JSON文件
- **导入配置**: 点击 **导入配置**，选择之前导出的JSON文件
  - 支持 **替换模式**（清空现有规则）
  - 支持 **追加模式**（保留现有规则）

#### 图片回复

1. 点击 **选择图片** 按钮
2. 在文件浏览器中选择图片文件
3. 支持的格式：JPG、PNG、GIF
4. 图片大小建议不超过5MB

## 👥 多账号管理

### 为什么移除了内置多账号功能？

内置多账号功能在实际使用中存在以下问题：
- 账号间可能相互影响
- 配置管理复杂
- 稳定性不够理想

### 推荐的多账号方案

#### 方案一：Docker 部署（推荐）

为每个账号创建独立的容器实例：

```bash
# 账号1 - 端口4999
docker run -d -p 4999:4999 -v biligo-data-1:/data --name biligo-1 biligo:latest

# 账号2 - 端口5000
docker run -d -p 5000:4999 -v biligo-data-2:/data --name biligo-2 biligo:latest

# 账号3 - 端口5001
docker run -d -p 5001:4999 -v biligo-data-3:/data --name biligo-3 biligo:latest
```

或使用本地目录挂载：

```bash
docker run -d -p 4999:4999 -v /path/to/account1-data:/data biligo:latest
```

**优点**：
- 完全隔离，互不影响
- 易于管理和维护
- 可以独立启动/停止
- 资源占用合理

#### 方案二：多开 BiliGo 实例

在不同目录运行多个 BiliGo 实例：

```bash
# 账号1
cd BiliGo-Account1
python app.py  # 默认端口4999

# 账号2（修改端口）
cd BiliGo-Account2
# 修改 app.py 最后一行为: app.run(host='0.0.0.0', port=5000, debug=False)
python app.py  # 端口5000

# 账号3（修改端口）
cd BiliGo-Account3
# 修改 app.py 最后一行为: app.run(host='0.0.0.0', port=5001, debug=False)
python app.py  # 端口5001
```

**访问地址**：
- 账号1: http://localhost:4999
- 账号2: http://localhost:5000
- 账号3: http://localhost:5001

**优点**：
- 简单直接，无需Docker
- 每个账号独立配置
- 互不干扰

#### 方案三：使用进程管理工具

使用 PM2 或 Supervisor 管理多个实例：

```bash
# 安装 PM2
npm install -g pm2

# 启动多个实例
pm2 start app.py --name biligo-account1 --interpreter python3
pm2 start app.py --name biligo-account2 --interpreter python3 -- --port 5000
pm2 start app.py --name biligo-account3 --interpreter python3 -- --port 5001

# 查看状态
pm2 list

# 查看日志
pm2 logs biligo-account1
```

## ❓ 常见问题

### 1. 登录状态失效怎么办？

**现象**: 系统提示"登录状态失效"或收到邮件通知

**解决方法**:
1. 重新获取 SESSDATA 和 bili_jct
2. 在 Web 界面更新配置
3. 重新启动监控

**预防措施**:
- 配置邮件提醒，及时收到通知
- 定期检查登录状态
- 避免在多个设备同时登录

### 2. 为什么没有收到邮件通知？

**检查清单**:
- ✅ 确认已启用邮件提醒
- ✅ 检查邮箱地址是否正确
- ✅ 确认使用的是授权码，不是QQ密码
- ✅ 检查邮箱的垃圾邮件文件夹
- ✅ 使用"发送测试邮件"功能验证配置

### 3. 触发了B站风控怎么办？

**现象**: 
- 发送消息失败，提示频率限制或 HTTP 412
- 日志显示「安全风控」或「网络错误」（旧版本误报）
- 无法获取关注者列表
- 多人同时出现相同发送失败（多为旧版共用设备 ID 导致）

**解决方法**:
1. **升级到 20260830 或更高版本**（已修复共用 `dev_id`、补充 `csrf_token` 等问题）
2. 在浏览器打开 [message.bilibili.com](https://message.bilibili.com) 手动发一条私信完成验证
3. 重启程序，确认 `config.json` 中已生成独立的 `im_dev_id`
4. 增加发送间隔（建议 2 秒以上）
5. 增加关注检查间隔（建议 30 分钟以上）
6. 暂停监控一段时间，关闭「默认回复」并开启「仅回复新消息」，避免启动时批量回复历史会话
7. 减少回复频率

**预防措施**:
- 不要设置过短的检查间隔
- 合理设置单用户最大回复次数
- 避免短时间内大量回复

### 4. 评论回复不工作？

**检查清单**:
- ✅ 确认已在评论回复页面启动监控
- ✅ 检查是否有新评论（程序只回复启动后的新评论）
- ✅ 确认评论规则已正确配置
- ✅ 查看评论日志了解详细情况
- ✅ 确认视频评论区未关闭

### 5. 图片回复失败？

**可能原因**:
- 图片文件过大（建议不超过5MB）
- 图片格式不支持（仅支持JPG、PNG、GIF）
- 网络问题导致上传失败

**解决方法**:
- 压缩图片大小
- 转换图片格式
- 检查网络连接

### 6. 如何备份配置？

**方法一**: 导出配置
- 点击 **导出配置** 按钮
- 保存JSON文件到安全位置

**方法二**: 备份文件
- 备份 `config.json`（私信配置）
- 备份 `keywords.json`（私信规则）
- 备份 `comment_config.json`（评论配置）
- 备份 `comment_rules.json`（评论规则）

### 7. 程序占用资源过高？

**优化建议**:
- 增加消息检测间隔（如改为0.1秒）
- 减少检查的视频数量
- 减少每个视频检查的评论数
- 定期清理日志

1. **遵守B站规则**
