1. 产品概览

BiliGo 是一个多平台自动回复管理工具，支持 B 站私信、B 站评论、抖音/小红书/微博私信，以及统一 AI 回复模式。

  • 私信模式（B 站）：自动处理用户私信，支持关键词规则、默认回复、按关注状态分流回复。
  • 评论模式（B 站）：自动检测视频评论并按规则回复。
  • 抖音私信模式：通过浏览器自动化监控抖音网页版私信，支持关键词规则与默认回复。
  • 统一 AI 回复模式：为 B 站私信、B 站评论、小红书、微博和抖音分别开启 AI 接管，并可绑定知识库。
  • 统一运行仪表盘：集中查看五个平台的消息、回复、成功率、运行状态和趋势变化。

系统通过轮询接口检测新消息或新评论，并按配置的频率与发送间隔执行回复，支持基础风控优化。

1.1 适用场景

  • UP 主需要在离线时自动处理常见咨询（合作、投稿、售后、资料索取等）。
  • 评论区互动量较大，需要先自动回应高频问题，再人工补充细节。
  • 希望降低“漏回消息/评论”的概率，并统一回复口径。

1.2 系统工作流

步骤 1：拉取
按配置间隔拉取私信会话或评论列表。
步骤 2：过滤
过滤历史数据、已回复对象、不满足条件的数据。
步骤 3：匹配
按规则顺序匹配关键词，未命中时进入默认回复。
步骤 4：发送
按发送间隔执行回复并写入缓存/日志。

2. 快速开始

先完成登录配置再启动监控。若未登录成功，后续规则设置不会生效。

2.1 第一次使用

  • B 站私信 / 评论：进入主界面后，先在账号配置中填写 SESSDATA 和 bili_jct，或使用扫码登录。配置规则后点击「开始监控」。
  • 抖音私信：切换到抖音私信页，点击「打开登录窗口」完成浏览器登录。详见 第 12 章 抖音私信模式。

2.2 基础建议

  • 先用较保守的检查间隔和发送间隔进行试运行。
  • 优先确认日志中有正常“检测-匹配-发送”链路，再逐步提高频率。

2.3 推荐初始化模板

模块建议初始值原因
消息监测间隔0.05 - 0.2 秒兼顾响应速度与资源占用
发送间隔1.0 - 2.0 秒降低风控与限流概率
评论检查间隔默认 5 秒，可按需调至 30 - 60 秒默认较快轮询。遇风控可拉长间隔
单用户最大回复次数3 - 5 次避免循环触发
抖音消息监测间隔0.5 - 1.0 秒浏览器自动化，不宜过快

2.4 上线前检查清单

  • 已保存登录信息，且可正常获取 UID。
  • 至少有一条启用规则，或默认回复已启用。
  • 日志页面可看到实时日志刷新。
  • 手动触发一次测试消息/评论，确认链路完整。

3. 私信模式

推荐顺序：登录配置 -> 默认回复/规则 -> 时间间隔 -> 开始监控 -> 查看日志。

系统先检测是否命中关键词规则，命中即优先规则回复。未命中时才走默认回复。

若不回复，优先看日志中是否出现“检测到消息”“规则命中”“发送成功/失败”三段链路。

3.1 系统控制

  • 开始监控/停止监控：启动或停止私信自动回复线程。
  • 仅回复新消息：只处理程序启动后的新私信，避免补回历史私信。
  • 单用户最大回复次数：限制同一用户的回复次数，防止循环回复。可勾选「不限制单用户回复次数」取消上限。

3.2 默认回复

  • 当消息未命中任何关键词时触发。
  • 支持文本回复与图片回复。
  • 支持“区分已关注/未关注用户”两套内容。

3.3 仅回复新消息机制说明

  • 启用后：只处理监控启动时间之后的新消息。
  • 关闭后：会处理未被缓存记录的历史会话消息。
  • 建议：首次部署先开启，稳定后再按业务需要决定是否关闭。

3.4 单用户最大回复次数说明

  • 按用户维度统计已回复次数，达到上限后跳过。
  • 适用于防止“关键词互相触发”或“用户反复发送同类内容”导致的连续回复。
  • 若需重新统计，可在管理功能中清理数据后重启监控。
注意：如果规则回复内容包含会触发对方自动回复的关键词，双方可能形成回环。请避免使用互相触发的短词。

4. 评论模式

评论模式默认建议较长检测间隔。频率过快容易触发平台限制。

4.1 入口

  • 主界面点击“切换到评论回复”进入评论页面。

4.2 监控配置

  • 评论检查间隔：检测新评论频率。
  • 回复发送间隔：控制单次回复节奏，降低风控风险。
  • 仅回复新评论：仅处理监控启动后出现的评论。

4.3 评论检测覆盖范围

  • 系统会先拉取你的视频列表，再按配置读取每个视频最近评论。
  • 若你视频很多，请适当提高“每轮检查视频数/每视频评论数”以提升覆盖。
  • 覆盖越大，API 请求越多。建议分阶段调优，不要一次拉满。

4.4 评论回复注意事项

  • B站评论回复仅支持文字；图片回复配置已移除。
  • 优先回复业务相关问题，避免对所有短评都回复。
  • 建议给“感谢类、提问类、合作类”分别建规则，减少误命中。
  • 如果评论区关闭或权限受限，日志会提示接口异常信息。

4.5 启动步骤

  1. 在评论页面完成 SESSDATA 和 bili_jct 配置，并保存。
  2. 配置评论默认回复或关键词规则；启用 AI 时跳过传统回复配置，改在统一 AI 页面设置。
  3. 点击“开始监控评论”，看到状态变为监控中后，再发送测试评论验证。

平台通用说明

小红书和微博使用独立的浏览器自动化会话、配置和规则文件。两个平台的操作界面基本一致，账号登录状态和监控状态也分别维护。

小红书私信

  1. 从主界面平台切换菜单进入“小红书私信”。
  2. 点击“打开登录窗口”，在浏览器中完成小红书登录；登录成功后返回页面确认账号昵称和登录状态。
  3. 在监控配置中设置消息检测间隔、发送间隔、仅回复新消息和单用户回复次数。
  4. 未启用 AI 时，在默认回复和关键词规则区域配置传统回复；可先保存规则再启动。
  5. 点击“开始监控”，状态显示“监控中”后，使用另一账号发送一条测试私信。

微博私信

  1. 从平台切换菜单进入“微博私信”。微博页面使用独立的微博浏览器会话，不会复用小红书登录。
  2. 点击“打开登录窗口”完成微博登录；必要时点击“刷新账号信息”确认昵称、UID 和头像已读取。
  3. 配置检测间隔、发送间隔、仅回复新消息和单用户回复次数。
  4. 未启用 AI 时配置默认回复和关键词规则；图片回复当前不可用，请使用文字回复。
  5. 点击“开始监控”，确认日志出现微博监控引擎已启动，再进行测试私信。

两个平台的通用注意事项

  • 首次启动会建立会话基线；开启“仅回复新消息”时，历史私信不会被批量回复。
  • 登录窗口关闭、Cookie 过期或浏览器运行时缺失时，监控无法启动；请先查看登录状态和运行日志。
  • 启用对应平台 AI 后，传统默认回复和关键词设置会锁定；返回平台页面后仍需点击“开始监控”。
  • 平台会话、规则和回复统计相互独立，调整一个平台不会改变其他平台。

5. 规则系统

私信与评论都支持规则列表。每条规则包含：

字段作用建议
规则标题用于管理和识别规则使用有业务含义的名称
关键词触发回复的匹配条件可用逗号分隔多个关键词
回复类型文本或图片图片路径需可被程序访问
启用状态控制规则是否生效临时停用优先于删除

匹配逻辑说明

  • 按规则顺序检测，命中后执行对应回复。
  • 未命中任何规则时，若启用了默认回复则走默认回复。

5.1 规则设计建议（实战）

  • 先写“精确意图”规则（如：合作、投稿、价格），再写泛化规则（如：你好、在吗）。
  • 同义词建议放在同一规则内，便于维护。
  • 避免将“谢谢”“好”等高频词单独放在最前，防止抢占匹配。

5.2 规则管理建议

  • 临时活动期可复制一份规则并命名为“活动_日期”。
  • 不确定是否需要删除时，优先“禁用”而不是“删除”。
  • 每次批量改规则后，建议立即导出备份。

5.3 规则匹配交互示例

输入一条示例消息，点击“执行匹配”，观察系统会命中哪条规则。

6. 关注与取消关注回复

  • 在“关注回复设置”中可切换配置“关注后回复”和“取消关注回复”。
  • 关注检测支持扫描页数、检测窗口、首次补发等参数。
  • 配置建议：
    • follow_check_interval 建议不低于 60 秒。
    • follow_scan_pages 建议 3-10 页按粉丝规模调整。
    • follow_new_window_seconds 根据业务场景调整。

6.1 参数含义补充

  • follow_scan_pages：每轮扫描关注列表的页数，页数越大覆盖越全。
  • follow_new_window_seconds：将关注时间在窗口内的用户视为“新关注”。
  • follow_backfill_on_first_run：首次启动时是否补发历史欢迎，慎用。
若你粉丝量较大，开启首次补发可能短时间触发大量发送，不建议直接在生产环境开启。

7. 时间与风控配置

若账号出现限流/风控，请第一时间拉长发送间隔与检测间隔，并降低同时处理量。

8. 账号与登录

8.1 推荐登录方式

  • 优先使用扫码登录，减少手工复制 Cookie 的错误率。
  • 若手工输入，请确保 SESSDATA 与 bili_jct 成对且有效。

8.2 登录失效表现

  • 日志中出现用户信息获取失败、接口认证失败等错误。
  • 此时需重新扫码或更新 Cookie。

8.3 登录配置注意事项

  • Cookie 过期后会出现“监控在运行但无有效处理”的现象。
  • 更换账号后，建议重启监控并观察首轮日志。
  • 不要在公开渠道泄露 SESSDATA 与 bili_jct。

9. 邮件提醒

系统支持错误通知邮件。你可以在主界面邮件配置中填写：

  • 发送邮箱（QQ 邮箱）
  • SMTP 授权码（非 QQ 登录密码）
  • 接收邮箱

建议先使用“测试邮件”确认配置可用，再启用正式提醒。

授权码不是邮箱登录密码。请在 QQ 邮箱安全设置中开启 SMTP 并生成授权码。

9.1 建议策略

  • 仅对关键错误启用提醒，减少噪声。
  • 确认接收邮箱可正常收信后，再在长期监控中启用。
  • 定期更换授权码并更新配置，提升安全性。

10. 导入导出

  • 导出配置：用于备份当前规则与参数。
  • 导入配置：支持替换模式与追加模式。
  • 从私信导入评论配置：可复用已有关键词规则，减少重复配置。
  • 抖音配置包：在抖音私信页可单独导出/导入，详见「12.7 导入导出说明」。

10.2 跨平台相互导入

五个平台页面均提供“从其他平台导入”：B站私信、B站评论、抖音私信、小红书私信和微博私信可以任意选择为源平台或目标平台。

  • 替换现有规则：清空目标平台的传统规则，再导入源平台规则。
  • 追加新规则：保留目标平台规则，并按关键词跳过重复项。
  • 同时映射检测间隔、发送间隔、仅回复新内容、回复次数和文字默认回复等通用参数。
  • 不复制账号、Cookie、登录会话、UID、统计、日志或浏览器 Profile。
  • 跨平台规则统一转换为文字回复；平台本地图片路径不会复制。
  • 目标平台启用 AI 时，传统规则处于锁定状态，需要先关闭该平台 AI 回复再执行导入。

10.1 导入前建议

  • 先导出当前配置作为回滚点。
  • 导入后先不开启监控，先检查规则数量与关键内容是否正确。
  • 确认无误后再启动监控，避免错误规则直接生效。

11. 日志与排错

  • 日志页支持按系统类型、级别、关键字筛选。
  • 优先关注 error 日志，定位登录、接口、发送失败等问题。
  • 若出现连续失败，先检查登录状态和网络，再检查回复规则配置。

11.1 快速定位法

症状优先检查常见原因
完全无回复监控状态、登录状态未启动/登录过期
有检测无发送规则与默认回复开关未命中且默认关闭
发送失败率高间隔、网络、风控频率过高/接口限制

12. 抖音私信模式

抖音模块通过 Playwright 控制 Chromium 浏览器访问抖音网页版私信，不依赖 Cookie 手工填写，首次登录后自动保存会话。

12.1 与 B 站私信的核心差异

对比项B 站私信抖音私信
登录方式Cookie / 扫码浏览器窗口扫码或密码登录
运行方式后台 API 轮询后台无头浏览器自动化
依赖环境Python + requests需安装 Playwright 与 Chromium
关注回复支持暂不支持
图片回复支持当前仅文本回复

12.2 快速开始

  1. 在主界面切换到「抖音私信」，或访问 /douyin。
  2. 点击「打开登录窗口」，在弹出的 Chromium 中完成抖音扫码或密码登录。
  3. 登录成功后关闭浏览器窗口即可，系统会自动保存会话。
  4. 配置默认回复或添加关键词规则，调整时间间隔与消息限制。
  5. 点击「开始监控」，在运行日志中确认出现「扫描到 N 个会话」等信息。
首次使用前请确保已安装 Playwright 浏览器依赖。若启动登录失败，请在本机执行 playwright install chromium 后重试。

12.3 系统控制

  • 开始监控 / 停止监控：启动或停止抖音私信监控线程。开始监控前会自动保存当前配置与规则。
  • 时间间隔配置（可折叠）：
    • 消息监测间隔：扫描私信会话列表的频率，最小 0.5 秒。
    • 发送等待间隔：两次自动回复之间的最小等待，最小 0.5 秒，建议 1 秒以上。
  • 仅回复新消息：启用后，首轮扫描仅建立会话快照，不回复启动前的历史私信。之后只处理新出现的未读或预览变化。
  • 单用户最大回复次数：限制同一用户的累计回复次数，建议 3–5 次。
  • 不限制单用户回复次数：启用后忽略上方次数上限，适合需要持续跟进的场景。
  • 导出配置 / 导入配置：备份或恢复抖音模块的规则与时间、消息等设置（不含登录会话）。

12.4 账号与登录

  • 打开登录窗口：弹出可见浏览器供你登录。成功后系统将会话写入本地存储。
  • 刷新账号：重新读取当前登录账号昵称、UID 与头像。
  • 退出登录：同时清除程序会话和对应浏览器中的 Cookie、站点存储及账号登录数据，需重新登录后才能监控。

登录状态保存在本地（如 douyin_storage.json 与浏览器 Profile），下次启动通常无需重复登录。若页面提示「登录状态已失效」，请重新打开登录窗口。

监控运行时会占用浏览器自动化资源。若同时手动打开抖音网页，可能与自动化进程冲突，建议监控期间避免同账号重复登录操作。

12.5 默认回复与规则

  • 默认回复：未命中任何关键词时发送。需勾选「启用默认回复」并填写内容。
  • 关键词规则：字段包括规则名称、关键词（逗号分隔）、回复内容、启用状态。
  • 从 B 站导入：一键复制 B 站私信页的关键词规则到抖音，便于多平台统一口径。
  • 匹配逻辑：按规则顺序检测，命中即回复。均未命中且默认回复已启用则发送默认内容。

12.6 推荐初始化参数

配置项建议初始值说明
消息监测间隔0.5 – 1.0 秒过低会增加浏览器负载与风控风险
发送等待间隔1.0 秒及以上两次回复之间留出缓冲
单用户最大回复次数3 – 5 次防止对同一用户反复触发
仅回复新消息建议开启避免启动时批量回复历史私信

12.7 导入导出说明

  • 导出配置：生成包含规则、时间间隔、默认回复、消息限制等设置的 JSON 文件。
  • 导入配置：支持「替换现有规则」与「追加到现有规则」两种模式。
  • 导入不会覆盖当前登录会话。换机迁移时需在新环境重新登录。
  • 导入前建议先导出一份当前配置作为回滚备份。

12.9 抖音专属常见问题

Q：为什么登录窗口一闪而过或打不开？
  • 确认本机已安装 Playwright 及 Chromium 运行时。
  • Docker 部署需使用带 Playwright 的镜像（如 Dockerfile.playwright）。
  • 查看运行日志中的具体报错信息。
Q：启用「仅回复新消息」后，为什么启动后一段时间仍不回复？
  • 首轮扫描会建立基线快照，避免误回历史消息。
  • 基线建立完成后，新未读或预览变化才会触发回复。
  • 可发送一条测试私信验证链路。
Q：能否与 B 站共用同一套规则？
  • 可使用「从 B 站导入」快速同步关键词规则。
  • 也可通过导出/导入 JSON 在多实例间迁移抖音配置。
  • 回复文案建议按平台分别微调，避免包含平台限制词。

13. 小红书私信模式

小红书私信通过 Playwright 浏览器自动化运行，登录会话、配置、规则和统计均独立保存。
  1. 从平台切换菜单进入“小红书私信”，点击“打开登录窗口”完成登录。
  2. 返回页面确认账号昵称和登录状态，设置检测间隔、发送间隔、仅回复新消息及单用户回复次数。
  3. 未启用 AI 时配置默认回复和关键词规则；启用 AI 时在统一 AI 页面开启“小红书”。
  4. 点击“开始监控”，状态变为“监控中”后发送测试私信。
  • 首次启动会建立历史消息基线，开启“仅回复新消息”不会批量回复旧消息。
  • 登录会话失效或 Playwright/Chromium 缺失时无法启动，请检查登录状态和日志。
  • 启用 AI 后传统默认回复和关键词设置会锁定，但仍需返回本页点击“开始监控”。
  • “导出配置”可下载小红书 JSON 配置包；“导入配置”支持替换或追加规则，不包含登录会话。

14. 微博私信模式

微博私信使用独立的微博浏览器会话，不会复用小红书登录状态。
  1. 从平台切换菜单进入“微博私信”，点击“打开登录窗口”完成微博登录。
  2. 必要时点击“刷新账号信息”，确认昵称、UID 和头像已读取。
  3. 设置检测间隔、发送间隔、仅回复新消息及单用户回复次数；未启用 AI 时配置默认回复和关键词规则。
  4. 点击“开始监控”，确认日志出现微博监控引擎已启动，再发送测试私信。
  • 微博当前使用文字回复，图片回复功能不可用。
  • 首次启动建立消息基线；开启“仅回复新消息”时不会处理历史私信。
  • 启用微博 AI 后传统回复设置会锁定，AI 配置保存后仍需点击“开始监控”。
  • “导出配置”可下载微博 JSON 配置包；“导入配置”支持替换或追加规则，不包含登录会话。

15. 闲鱼消息模式

从平台切换菜单进入闲鱼消息页，点击“打开登录窗口”并在闲鱼网页完成登录。登录成功后可配置默认回复、关键词规则、回复间隔和单用户回复上限。

使用建议：首次运行请保持“仅回复启动后收到的新消息”开启，并先用测试账号发送消息验证页面结构。闲鱼网页更新后若日志持续提示无法读取会话，请停止监控后重新登录，避免误发。

15. AI 回复

AI 回复使用你配置的模型服务，根据平台收到的私信或评论自动生成回复。所有 AI 功能集中在“统一 AI 回复设置”页面，包括提供商、大模型运行参数、多知识库、五个平台开关和人工待回提醒。

15.1 面板结构与生效条件

AI 提供商
配置协议、Base URL、模型和 API Key，并获取模型列表或测试连接。
大模型 AI 配置
控制上下文窗口、自动压缩以及违禁词拦截。
知识库配置
创建或上传知识库，并把一个或多个知识库分配给不同平台。
人工待回
查看 AI 标记的疑似需人工处理消息，并快速回复或忽略。

AI 实际接管某个平台必须同时满足三个条件：顶部“启用 AI 回复”总开关已打开、对应平台开关已打开、该平台监控已经启动。左侧“0 / 6”会显示当前已开放的 AI 平台数量。

修改提供商、运行参数、平台开关或知识库分配后，需要点击页面底部“保存设置”才会生效。仅切换标签或返回平台不会自动保存。

15.2 配置 AI 提供商

设置项填写方法说明
协议格式选择 OpenAI 兼容、Anthropic 兼容或自定义兼容自定义兼容使用 OpenAI 风格的聊天补全与 Bearer 鉴权；必须与服务商接口格式一致
接口地址填写服务商提供的 API Base URL通常填写到 /v1；不要重复拼接聊天补全路径
模型名称手动输入模型 ID，或从获取到的模型列表中选择应填写接口实际接受的模型 ID，不一定等于产品展示名称
API Key填写服务商密钥保存在本机；再次打开时显示星号，不修改星号会继续使用已保存密钥
  • 获取模型列表：先填写 Base URL 和 API Key，再点击模型输入框右侧按钮。成功后可从下拉列表选择；某些兼容服务商未开放模型列表接口时，可直接手动填写模型 ID。
  • 延迟测速：检测模型列表接口的网络往返时间，结果分为“优秀、良好、较慢”。它反映连接延迟，不等同于模型生成完整回复所需时间。
  • 测试连接：使用当前模型发送一次很短的生成请求，用于同时检查地址、鉴权、模型名和聊天接口是否可用。

15.3 大模型 AI 配置

设置项默认值作用
上下文开关开启按平台、按用户读取此前已确认发送成功的对话，并加入平台回复要求和已分配知识库；关闭后仅依据当前消息生成
上下文窗口大小6000限制单次提示内容长度，可设置 500 至 128000；修改数值后会自动保存，实际上限仍受所选模型限制
自动压缩开启内容超出窗口时优先保留靠后的最新内容；关闭后保留窗口开头部分
违禁词空使用中文逗号“，”分隔；用户消息命中后自动回复“您发送的消息含有敏感或违禁词”

会话上下文在本机持久化，不同平台及不同用户之间相互隔离。只有平台确认回复发送成功后，该轮用户消息和回复才会写入上下文；发送失败不会污染后续对话。启用功能前的旧聊天不会自动伪造或补录，从启用新版上下文后的成功对话开始积累。

违禁词会在调用模型前进行确定性拦截。涉及合规、隐私、金额或承诺的业务，建议同时启用人工待回并进行人工复核。

15.4 按平台启用与传统规则的关系

在“平台设置”中可分别打开 B站私信、B站评论、小红书、微博和抖音开关，只让需要的平台交由 AI 接管。

  • 总开关关闭时，所有平台的 AI 均不生效，即使单个平台开关仍处于打开状态。
  • 某个平台启用 AI 后，该平台的默认回复和关键词规则会停用并锁定，避免同一条消息被两套逻辑同时处理。
  • 未启用 AI 的平台继续使用原有关键词规则和默认回复，平台之间互不影响。
  • 保存 AI 设置并不等于启动监控；返回相应平台后仍需点击“开始监控”。
  • 从哪个平台进入 AI 设置，右上角“返回平台”就会返回该来源平台。

15.5 创建、上传和分配知识库

  1. 进入“知识库配置”，打开“启用知识库”。
  2. 点击“新建”，填写知识库名称和正文，再点击“保存知识库”。适合录入常见问答、产品资料、售后政策和品牌语气。
  3. 也可点击“上传 MD”，选择 UTF-8 编码的 .md 或 .markdown 文件。单个文件须在 2MB 以内，系统会以文件名创建知识库并展示原文供继续编辑。
  4. 切换到各平台标签，在“使用知识库”中勾选该平台需要的一个或多个知识库。
  5. 点击页面底部“保存设置”，保存知识库总开关和五个平台的分配关系。
  • “保存知识库”只保存当前知识库的名称和内容；平台勾选关系仍由页面底部“保存设置”统一保存。
  • 一个知识库可以同时分配给多个平台，一个平台也可以组合使用多个知识库。
  • 启用知识库但某个平台没有勾选任何知识库时，该平台不会获得知识库内容，AI 仍可能使用通用能力回答。
  • 知识库列表右侧“×”会删除整个知识库，并从所有平台分配中移除。重要内容请先自行备份。

15.6 人工待回提醒

“人工待回”默认关闭。开启后，AI 在生成回复的同时判断当前问题是否缺少可靠信息或需要人工权限；判定需要人工时不会自动发送回复，而是把消息加入待处理列表。

  • 常见触发场景包括：知识库不足以支持具体业务结论、订单与退款、支付、账号权限、投诉争议、法律或隐私问题，以及用户明确要求人工。
  • AI 服务暂时不可用、无法生成可靠回复时，也会优先加入人工待回，避免发送不确定内容。
  • 左侧“人工待回”角标显示全部平台的待处理数量；列表每 15 秒自动刷新，也可手动刷新并按平台筛选。
  • 卡片会显示来源平台、发送者、原消息、AI 判断原因和时间。输入人工回复后点击“发送回复”，也可按 Ctrl/Command + Enter 快速发送。
  • 点击“忽略”只会将该条记录标记为已处理，不会向对方发送任何内容。
  • 人工发送失败时消息会保留在待回列表中，可检查平台登录状态后重试。
人工待回列表为了支持人工判断和定向回复，会在本机保存消息正文、发送者显示信息及必要的回复目标。若在此标签修改开关，请切换到其他设置标签点击“保存设置”。

15.7 推荐配置与上线顺序

  1. 完成目标平台登录，确认账号状态正常。
  2. 配置 AI 提供商，先获取或填写模型，再执行“测试连接”。
  3. 按模型能力设置合理的上下文窗口和安全词约束。
  4. 创建知识库、打开知识库总开关，并为目标平台分配内容。
  5. 按业务风险决定是否开启“人工待回”；首次使用建议开启后先观察判断效果。
  6. 打开 AI 总开关及目标平台开关，点击“保存设置”。
  7. 返回平台启动监控，用真实测试消息检查自动回复、人工待回和日志链路。

15.8 运行边界与故障处理

现象检查方法
测试连接失败检查协议格式、Base URL、API Key、模型 ID、余额/额度和网络；HTTP 状态码通常来自服务商
获取不到模型列表兼容服务商可能没有 /models 接口；若测试连接可用，可手动填写模型 ID
保存后没有 AI 回复确认总开关、平台开关和平台监控三者都已开启，并检查运行日志
知识库内容未生效确认知识库总开关已开、目标平台已勾选该库，并点击了页面底部“保存设置”
传统规则无法编辑该平台正在由 AI 接管；需要先关闭对应平台 AI 开关并保存
人工快速回复失败回到来源平台检查登录会话和监控环境；浏览器自动化平台还需确认私信页面可正常打开
AI 生成失败时不会自动套用传统默认回复。未开启人工待回时，该消息会被跳过并记录失败；开启人工待回时，会尽量进入待处理列表供人工接管。

15.9 安全与风控建议

  • 不要把 API Key 提交到公开仓库、截图或日志中，并定期在服务商后台轮换密钥。
  • 先在单个平台、低消息量场景试运行，确认回答风格和知识库边界后再扩大范围。
  • 知识库中不要写入不必要的身份证号、银行卡号、访问令牌等敏感信息。
  • 不要让模型自行承诺退款、赔偿、价格或法律结论；此类问题应交由人工待回。
  • 模型输出仍可能存在错误。高风险业务应保留人工复核和平台日志审查流程。

16. 运行仪表盘

运行仪表盘用于集中查看 B站私信、B站评论、抖音私信、小红书私信和微博私信的整体运行情况。它只展示聚合统计，不替代各平台的配置、日志或监控开关。

五个平台的顶栏均提供“仪表盘”入口。仪表盘会记住进入前的平台，点击右上角“返回平台”即可回到原页面。

16.1 打开与刷新

  1. 进入任意平台页面，在顶栏点击“仪表盘”。
  2. 页面默认展示最近 30 天数据，也可切换为 7 天、90 天或全部时间。
  3. 仪表盘每 30 秒自动同步一次；需要立即查看最新结果时，点击右上角“刷新”。
  4. 顶栏显示“自动同步”表示最近一次读取成功；显示“同步失败”时可检查服务状态并手动重试。

16.2 顶部核心指标

指标含义注意事项

16.4 平台状态卡

底部五张状态卡分别展示平台运行状态、周期收到/成功数量、触达用户、成功率、回复规则数量和最后活动时间。多账号平台还会显示账号数量。

  • 运行中：监控线程正在工作。
  • 未运行：配置可能正常，但当前没有启动监控。
  • 未配置或登录失效：返回对应平台完成登录或配置后，再启动监控。
  • 状态未知：该平台状态暂时无法读取，其他平台数据仍会正常显示。

16.5 历史数据与统计口径

  • 首次启用仪表盘时，会读取 B站私信、抖音、小红书和微博已有的累计回复次数，加入“累计成功回复”。
  • 启用前的历史累计不会被虚构分配到某一天，因此不会出现在日趋势中；准确的日趋势从仪表盘统计功能上线后开始。
  • B站评论没有旧的按用户累计基线，从仪表盘功能上线后的新评论开始统计。
  • 同一条消息或同一次回复会通过事件标识去重，正常的重复轮询不会重复累计。
  • 重置单个平台数据时，该平台的仪表盘数据会同步清理；“清除所有数据”会清空全部仪表盘统计。

16.6 隐私与常见排查

  • 仪表盘统计保存在本机 SQLite 数据库中，不记录消息正文、昵称或原始用户 ID；联系人仅以不可逆哈希用于去重计数。
  • 刚启动监控但数字没有变化时，先确认收到的是新消息，并查看对应平台日志是否完成了检测或发送。
  • “累计成功回复”与当前周期成功数不同是正常现象：前者包含全部历史累计，后者只统计所选周期。
  • 平台显示未运行时，请回到对应平台检查登录状态，然后点击“开始监控”。

17. 常见问题

Q1：为什么没有自动回复？
  • 监控未启动。
  • 默认回复未开启且规则未命中。
  • 启用了“仅回复新消息/新评论”，当前内容被判定为历史数据。
  • 登录状态失效。
Q2：如何降低风控风险？
  • 增大发送间隔与检查间隔。
  • 限制单用户回复次数。
  • 避免短时间高频批量回复。
Q3：规则命中不稳定怎么办？
  • 检查关键词是否过短、是否有错别字。
  • 检查规则是否被禁用、排序是否合理。
  • 查看日志确认是否进入“规则匹配”环节。
Q4：为什么会重复回复同一用户？
  • 检查单用户最大回复次数是否设置过高。
  • 检查是否频繁重启并清空了统计缓存。
  • 检查是否存在多条规则命中同类消息。
Q5：如何安全更新配置？
  • 先导出备份，再调整配置。
  • 每次只改一类参数，观察日志后继续。
  • 出现异常立即回滚到上一次导出配置。
